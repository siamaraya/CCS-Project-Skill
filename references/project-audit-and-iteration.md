# ตรวจและต่อยอดโครงการ CCS เป็นรอบ

วิธีนี้เป็น **กระบวนการประยุกต์ของ Skill** สำหรับโครงการที่มีเอกสาร แผน หรือผลทดลองอยู่แล้ว. ใช้หลักการใน [ccs-framework.md](ccs-framework.md) และวิธีวัดใน [impact-measurement.md](impact-measurement.md). รายงานตามความลึกที่ผู้ใช้ต้องการ; ไม่ต้องสร้างเอกสารหลายไฟล์เพื่อการตอบคำถามสั้นครั้งเดียว.

## 1. ตรึงสถานะที่กำลังตรวจ

บันทึกชื่อโครงการ เวอร์ชัน/วันที่ของแผน ช่วงเวลาข้อมูล เอกสารหรือไฟล์ที่อ่าน และเรื่องที่ยังไม่เข้าถึง. แยก **สิ่งที่วางแผน**, **สิ่งที่ทำแล้ว**, **ผลที่สังเกต**, และ **สิ่งที่คาด**. ถ้าข้อมูลมีหลายรุ่น ให้ระบุว่าข้อสรุปใดอิงรุ่นไหน; อย่าเขียนทับประวัติการตัดสินใจ.

## 2. ตรวจหลักฐานและคำอ้าง

ทำบัญชีสั้น ๆ สำหรับคำอ้างที่กระทบการตัดสินใจ: รหัสหลักฐาน, แหล่ง/ตำแหน่ง, วันที่, สิ่งที่แหล่งกล่าวหรือวัดจริง, ข้อจำกัด, และคำอ้างที่รองรับ. ระบุชั้นความเชื่อมั่นเป็นคำบรรยายตามเหตุผล เช่น “มีผลวัดจาก pilot เดียวและไม่มี baseline”. อย่าสร้างเปอร์เซ็นต์ความมั่นใจหากไม่มีวิธีคำนวณ.

สถานะที่ใช้กับแต่ละข้อ:

- **มีหลักฐานรองรับ:** ระบุหลักฐานและขอบเขตที่รองรับได้.
- **ยังไม่มีหลักฐานพอ:** ยังตัดสินไม่ได้; ระบุข้อมูลที่ต้องหา.
- **ขัดกับหลักฐาน:** แหล่งที่มีอยู่ชี้ไปอีกทาง; แสดงทั้งสองด้าน.
- **ยังไม่เกี่ยวในระยะนี้:** อธิบายว่าทำไมและเมื่อใดต้องกลับมาตรวจ.

ข้อมูลจากผู้ใช้และเอกสารโครงการเป็นหลักฐานว่าโครงการ **รายงาน** เช่นนั้น. เมื่อจะยืนยันข้อมูลภายนอกที่เปลี่ยนได้ เช่น กติกา ปริมาณผู้ได้รับผล หรือวิธีเดิมในพื้นที่ ให้ตรวจแหล่งต้นทางที่เหมาะสม. อย่าส่งข้อมูลส่วนตัวของผู้เกี่ยวข้องออกไปค้นโดยไม่จำเป็น.

## 3. ตรวจแกน CCS

ตรวจ **Capstone/Cornerstone**, เกณฑ์ **New Idea, Specific Issue, For the Commons, Implementable, Start Small, High Impact**, และหลักฐานของ **Ideation / Implementation / Impact Innovation**. ติดสถานะข้างต้น พร้อม “เหตุใดช่องว่างนี้สำคัญ” และทางแก้ที่ทำได้. ตรวจผลสองทางแยกกัน: คุณค่าต่อผู้ได้รับผล และการเรียนรู้/ความร่วมมือของทีม. จำนวนกิจกรรม ผู้เข้าร่วม หรือสื่อประชาสัมพันธ์ยังไม่ยืนยัน Impact Innovation.

เมื่อแนวคิดคลุมหลายปัญหา ให้ช่วยเลือกปัญหาหลักหรือแยกโครงการ. เมื่อความใหม่ไม่ชัด ให้ระบุงานเดิมและสิ่งที่ต้องค้น. เมื่อไม่มีสิทธิ์/งบ/คน ให้ลดขนาดการทดลองหรือกลับไปอยู่ระดับ CCS Spirit. เมื่อผลดีมีเพียงคำบอกเล่า ให้เสนอวิธีเก็บข้อมูลที่เหมาะกับขนาดงาน.

## 4. เรียงช่องว่างและวางรอบถัดไป

เรียงตามผลต่อความถูกต้องของข้อสรุป ประโยชน์ต่อส่วนรวม และความเป็นไปได้ในการลงมือ. ใช้ระดับความสำคัญเชิงปฏิบัติ ไม่ใช่คะแนน CCS:

- **สูง:** ทำให้เลือกโจทย์ผิด ลงมือไม่ได้ เสี่ยงกระทบผู้คน หรืออ้างผลเกินหลักฐาน; ต้องจัดการก่อนขยาย.
- **กลาง:** ทำให้การทดลองหรือการวัดอ่อน แต่ยังมีวิธีทดสอบที่ปลอดภัยในขอบเขตจำกัด.
- **ต่ำ:** ปรับถ้อยคำ รายละเอียด หรือความสะดวก โดยไม่เปลี่ยนการตัดสินใจหลัก.

ทุกข้อเสนอควรเชื่อม `ข้อค้นพบ → การแก้หรือสมมติฐาน → การลงมือครั้งถัดไป → หลักฐานที่จะเก็บ → เงื่อนไขตัดสินใจ`. ระบุผู้รับผิดชอบและเวลาเมื่อมีข้อมูล; ถ้าไม่มี ให้ทำเครื่องหมายว่า **ต้องกำหนด**. เลือกงานรอบถัดไปเท่าที่ทรัพยากรรับได้. การต่อยอดอาจเป็นการ **ปรับโจทย์, ทดสอบความใหม่, ทดลองเล็ก, วัดผล, ทำซ้ำ, ขยาย หรือหยุด** ไม่จำเป็นต้องเป็นการขยายขนาดทุกครั้ง.

## 5. ส่งมอบและรักษาความต่อเนื่อง

สำหรับงานครั้งเดียว ให้สรุปข้อค้นพบสำคัญ สถานะหกเกณฑ์/3I เท่าที่เกี่ยวข้อง และการกระทำถัดไป. สำหรับโครงการที่ทำหลายรอบ ให้ใช้ [รายงานตรวจ](../assets/project-review-report.md), [บัญชีหลักฐานและบันทึกการตัดสินใจ](../assets/evidence-and-decision-log.md), และ [แผนรอบถัดไป](../assets/next-cycle-plan.md). เมื่อกลับมาตรวจใหม่ ให้เพิ่มรอบ/วันที่และสรุปความต่างจากรอบก่อน โดยเก็บร่องรอยข้อสรุปเดิม ไม่เปลี่ยน “คาดว่าจะเกิด” ให้กลายเป็น “เกิดแล้ว” เพียงเพราะเวลาผ่านไป.

ผลลัพธ์ที่ดีควรทำให้ผู้อ่านตอบได้ว่า **ตอนนี้รู้อะไรจากหลักฐาน, ยังไม่รู้อะไร, ทำอะไรต่อ, ใครทำ, และจะรู้ได้อย่างไรว่าควรไปต่อ**.
